# Design Critique

Read [the shared product principles](../../harness/references/product-principles.md).

## Workflow

1. Establish the intended user, job, context, business purpose, constraints, and maturity of the artifact.
2. Inspect the whole journey before commenting on isolated details.
3. Evaluate information hierarchy, affordances, feedback, consistency, accessibility, trust, errors, recovery, and edge states.
4. Trace issues to user impact and strategic consequence.
5. Distinguish observed problems from taste, assumptions, and optional refinements.
6. Prioritize the few changes with the highest user value and decision impact.

## Output

Lead with the most consequential findings. For each, state the evidence in the artifact, affected user or scenario, impact, and correction direction. Note strengths only when they should be preserved through revision.

Avoid generic advice, aesthetic preference disguised as principle, and exhaustive annotation without prioritization.
