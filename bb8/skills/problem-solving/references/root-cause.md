# Root-Cause Analysis

## Choose the mode

- Use **Five Whys** to deepen one plausible causal chain.
- Use a **fishbone** to widen the search across categories.
- Use both when the cause space is broad and individual chains need validation.

## Five Whys

Start with a specific observed event. At each step ask why it occurred, then require evidence or mark the answer as a hypothesis. Branch when several causes plausibly contributed. Stop when the next answer becomes outside scope, unsupported, or no longer actionable—not when five questions have been asked.

Reject endpoints such as “carelessness,” “poor communication,” or “human error” unless the operating conditions that made the behavior likely are explained.

## Fishbone

Choose categories suited to the system rather than defaulting mechanically. Candidate categories include people, process, technology, data, incentives, environment, policy, measurement, materials, and demand.

Populate candidate causes, then test them. A fishbone is a hypothesis inventory, not a finding.

## Validate causes

For each candidate ask:

- Did it precede the outcome?
- Is there a credible mechanism?
- Does variation in the cause track variation in the outcome?
- What evidence would falsify it?
- Would removing it reduce recurrence?
- Is it a cause, contributing condition, trigger, or correlation?

## Finish with intervention points

Separate the deepest historical cause from the most effective controllable intervention. Recommend controls at multiple levels when prevention, detection, and recovery all matter.
