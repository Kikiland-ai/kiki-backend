## Seven prototype boundaries

1. Grounded bilingual lesson compiler: sources/translation → structured content and visual teaching intent.
2. Mixed-language TTS: speech plans/pronunciation → audio and real timing cues.
3. Graphics engine: reviewed visual spec → editable animated scene, GIF, and poster.
4. Annotated teaching canvas: audio + scene/image + annotation layers → synchronized instruction.
5. Learner graph/curation: assessment evidence → evolving state and targeted next activity.
6. Diagnostic assessment/exam repair: answer → criterion evidence, image markup, repair, retest.
7. Live screen annotation/lab copilot: fresh observations → temporary guided cues, verified checkpoints, saved session.

## Options and tradeoffs

Prefer coherent sentence-level code-switched synthesis if it passes review; use phrase/sentence segmentation with reviewed continuity if needed. Do not assume a provider supports Odia, pronunciation controls, or accurate alignment. Sentence timing is acceptable before trustworthy word timing.

Use declarative scene/template rendering for scientifically controllable geometry and animation; optional generated illustration assets can be placed beneath precise labels/overlays. GIF is a required export; editable scenes/seekable derivatives support synchronized playback. Teaching images use stable asset coordinates; live screens require fresh anchors and invalidation.

One API with internal modules and media workers minimizes prototype deployment complexity. Playback/rendering/geometry and actual external-tool overlay execution belong on the client. Evidence and curation are separate internal responsibilities even though they form one numbered feature prototype.

## Dependencies and priorities

Content ids/spans link speech, visual objects, and evaluations. Actual audio timings feed composition. Scene ids and asset transforms anchor image annotations. Assessments/lab observations populate the learner graph. Curation selects content/format without inventing evidence. Lab cues reuse speech/drawing primitives but are checkpoint-driven.

## Risks, controls, and unblockers

- Speech might be intelligible in one language but fail at language switches/technical values: use bilingual review and a pronunciation lexicon; labelled recordings are only a fixture fallback.
- Animation might be visually convincing but scientifically wrong: constrain scenes to reviewed templates and validate quantities/semantics.
- Timed cues might drift or survive language changes: actual audio clock, stable semantic ids, and cancellation/version rules.
- Image annotations might move under resize/crop: source coordinates with explicit transforms.
- Live arrows might point at stale targets: workspace/capture versions, geometry mapping, invalidation, and pause/re-observation.
- Simulink integration might be unavailable: trial early; use clearly labelled screenshot/manual companion guidance if necessary.
